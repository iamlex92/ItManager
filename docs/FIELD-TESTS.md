# Протокол испытаний на реальном оборудовании

Эти проверки нельзя выполнить без заводской сети и настоящих компьютеров. Для каждой: шаги, ожидаемый результат,
куда записать итог. Проводит владелец, результат возвращает исполнителю (что получилось, текст ошибки, скриншот).

Отметка в конце каждого пункта: **ОК** / **не ОК** + дата + кто проверил.

## 1. Синхронизация между двумя настоящими серверами
1. На резервном сервере: «Параметры сервера → Резервный сервер» → «Принимать базу» включить, перезапустить.
2. На основном: адрес и токен резервного сервера, «Проверить связь» — все пункты с галочкой.
3. «Синхронизировать сейчас». Ожидание: в журнале `sync:push`, на резервном «последняя база» свежая,
   устройства совпадают.
4. На резервном сервере попробовать изменить устройство. Ожидание: отказ «только чтение».
5. Выключить основной. В приложении: плашка «Резервный сервер · только чтение · база от …», карта открывается.
6. Включить основной. Ожидание: приложение возвращается на основной в течение минуты (или кнопкой «Вернуться
   на основной сейчас»).
7. Разные `SECRET_KEY` на серверах: «Проверить связь» показывает «SECRET_KEY разный», отправка отклоняется.

## 2. Этикетки QR на телефонах
Напечатать этикетки (A4, мелкие, 50×30 мм) и навести камеру: MIUI, Samsung, чистый Android.
Ожидание: предлагается открыть NetAdmin, открывается карточка нужного устройства; на телефоне без приложения
сообщение понятное. Для каждого телефона записать: модель, версия Android, что произошло.

## 3. Теневое подключение RDP («Подключиться напрямую»)
1. Компьютер с политикой «полный контроль без разрешения пользователя»; пользователь вошёл.
2. «Компьютеры» → компьютер → «Подключиться напрямую». Ожидание: список сеансов (qwinsta) разобран,
   подставлена команда `mstsc /shadow:<ID> /v:<имя> /control /noConsentPrompt`.
3. Проверить русскую и английскую Windows, сеанс консоли и RDP-сеанс, отключённый сеанс.
4. Записать вывод `qwinsta` с компьютера, если разбор ошибся.

## 4. Удалённая помощь на Astra Linux
x11vnc при включённом мандатном контроле целостности (MIC): подключиться к рабочему столу, управлять мышью.
Записать версию Astra и текст ошибки, если не получилось.

## 5. Cisco Secure Client (VPN завода)
Из приложения: подключить, отключить после «Домой». Записать версию клиента и поведение на разных телефонах.

## 6. Свои скрипты
Запуск на Windows (WinRM) и Astra (SSH): вывод виден, код возврата верный, повторный запуск на том же компьютере
отклоняется («уже выполняется»), закрытие вкладки останавливает серверный скрипт.

## 7. Групповые политики на Samba
Создание GPO, связь с подразделением, шаблоны на реальных компьютерах (`gpupdate /force`, `gpresult`).
Проверить права учётной записи на Samba; записать ошибки LDAP.

## 8. Тайм-аут WinRM
Выключенный компьютер: действие завершается ошибкой за время из настройки, а не висит. Записать время.

## 9. Нагрузка
База с 5000 устройств: открытие карты, список, поиск, «Обновить». Записать время ответа и память сервера.
