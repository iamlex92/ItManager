# ItManager · NetAdmin DCIM

Мобильный центр управления IT-инфраструктурой завода: план здания с кабельной топологией,
коммутаторы Cisco и Eltex, МФУ и регламентные операции. Рассчитан на Google Pixel 10a (Android 16).

Репозиторий содержит два проекта:

| Папка | Что внутри |
| --- | --- |
| `app/` | Android-приложение (Kotlin, Jetpack Compose) |
| `server/` | Сервер NetAdmin (Python, FastAPI), описание API в `server/API.md` |

## Android-приложение

**Стек:** Kotlin 2.2, Jetpack Compose + Material 3, Hilt (внедрение зависимостей), Ktor Client,
kotlinx.serialization, DataStore, Navigation Compose. `minSdk 31`, `targetSdk 36`.
Интерфейс только на русском и только в тёмной теме.

### Что уже есть (этап 1)

- **Карта.** План этажа с жестами: перемещение и масштаб двумя пальцами, инерция после броска,
  мягкое сопротивление у краёв, двойной тап для приближения. Слои L1 (кабели), L2 (VLAN), L3 (IP-подсети),
  фильтр по VLAN. Тап по устройству показывает карточку и подсвечивает путь до коммутатора:
  ПК → розетка → патч-панель → коммутатор.
- **Устройства.** Поиск по имени, IP и MAC, фильтры по типу, переход к устройству на карте.
- **Коммутатор.** Лицевая панель портов как на железе (нечётные сверху, чётные снизу, SFP отдельно),
  цвета по спецификации: зелёный 1/10 Гбит/с, оранжевый 10/100, серый нет линка или shutdown, молния для PoE.
  Карточка порта с режимом, VLAN, скоростью и подключённым устройством. Изменение конфигурации пока недоступно.
- **Вид портов по VLAN.** Переключатель «По статусу / По VLAN» над панелью: в режиме VLAN порт окрашен цветом своего VLAN,
  trunk показан полосами по разрешённым VLAN с чертой снизу, порт без линка бледный. Нажатие на VLAN в легенде подсвечивает его порты
  и показывает, сколько их и сколько с линком.
- **МФУ.** Уровни тонера и барабана, предупреждение ниже 10 %, проблемные МФУ наверху списка.
- **Автоматизация.** Каталог будущих сценариев (AD, права на папки, резервные копии), без запуска.
- **Настройки.** Адрес сервера, API-токен, проверка соединения, переключатель демо-данных.

### Этап 3

- **План здания с сервера.** SVG из `plan_image_url` рисуется под устройствами векторно, без потери чёткости
  при приближении, и перекрашивается под тёмную тему.
- **Поиск на карте** по имени, IP, MAC или номеру розетки: карта плавно перелетает к устройству
  и подсвечивает путь до коммутатора.
- **Живой статус** через WebSocket `/api/v1/ws`: порты коммутатора меняют цвет без обновления экрана,
  точки «в сети» на карте следуют за сервером. При обрыве связи приложение переподключается само.
  В демо-режиме свободные порты время от времени теряют и восстанавливают линк, чтобы было видно, как это выглядит.

### Этап 4: управление портами

- В карточке порта: режим Access или Trunk, выбор VLAN, включение и выключение порта (shutdown).
  Сначала приложение показывает точные команды Cisco или Eltex, применяет только после подтверждения.
- Перезапуск порта: shutdown, пауза 2 секунды, no shutdown.
- Аплинки защищены отдельной галочкой: без неё сервер изменение не примет.
- «Сохранить конфиг» (write memory) и «Сравнить конфиг»: сохранённая копия против текущей running-config.
- Ping и traceroute с самого коммутатора: выбрать устройство из списка или ввести IP, вывод показывается как в консоли.
  Это только чтение, подтверждение не нужно. Для реального железа сервер пока отвечает «не реализовано».
- Защита оборудования на сервере: в режиме реального железа изменения выключены, пока на сервере не задан
  `ALLOW_DEVICE_WRITES=true`. Каждая попытка, даже заблокированная, пишется в журнал аудита.
  В демо-режиме изменения остаются на телефоне.

### Этап 5: NFC, МФУ, события

- **NFC-метки (NTAG213/215/216).** Поднесите телефон к метке: коммутатор откроется на панели портов,
  остальное оборудование покажется на карте. Работает и при закрытом приложении.
  На метку пишется JSON из спецификации (`{"app":"netadmin","v":1,"id":…,"type":…,"name":…}`),
  если места мало, имя не пишется, остаётся id.
- **Привязка метки.** «Привязать NFC-метку» в карточке устройства на карте или «NFC-метка» на экране коммутатора.
  Сервер запоминает UID метки, затем на метку записываются данные устройства. Если метка уже привязана
  к другому устройству, приложение спросит, переносить ли её. Само оборудование при этом не трогается.
- **МФУ.** Уровни тонера, фотобарабана и свободного места в отработке по данным SNMP-опроса сервера,
  предупреждение ниже 10%, отметка «не отвечает», время последнего опроса и кнопка «опросить сейчас».
  Новые показания приходят сами по WebSocket.
- **События.** Колокольчик в верхней панели со счётчиком открытых событий, экран событий
  (открытые и все, «Решено», переход к устройству). Пока приложение на экране, новое событие
  всплывает баннером сверху. Push в фоне (FCM) не сделан: для него нужен проект Firebase.

### Демо-режим и сервер

По умолчанию включены **демо-данные**: встроенный пример цеха, сервер не нужен,
реальное оборудование не затрагивается. Чтобы работать с сервером:

1. Откройте ⚙ в правом верхнем углу любой вкладки.
2. Укажите адрес сервера, например `10.0.0.5` (порт 8000 подставится сам) или `http://10.0.0.5:8000`.
3. Вставьте API-токен, нажмите «Проверить соединение», выключите демо-данные и сохраните.

Сервер доступен только из сети завода или через VPN и наружу не публикуется.
Поэтому приложение разрешает обычный HTTP (см. `app/src/main/res/xml/network_security_config.xml`).
Когда у сервера появится сертификат внутреннего УЦ, достаточно указать адрес с `https://`.

### Сборка

Свежая тестовая сборка из master всегда лежит на странице релиза **ItManager: тестовая сборка**
(Releases → `android-latest`): откройте её на телефоне и нажмите `itmanager-debug.apk`.
Сборки подписаны общим тестовым ключом (`app/debug.keystore`, не секрет) и нумеруются по запуску CI,
поэтому новая версия ставится поверх старой.

APK любой ветки и pull request тоже есть в GitHub Actions: вкладка **Actions** → запуск **Android** →
артефакт `itmanager-debug-apk`.

Локально нужны JDK 17 и Android SDK (проще всего через Android Studio):

```bash
./gradlew testDebugUnitTest   # юнит-тесты
./gradlew assembleDebug       # app/build/outputs/apk/debug/app-debug.apk
```

### Устройство кода

```
app/src/main/java/com/itmanager/app/
├── core/network     Ktor-клиент, DTO сервера, понятные тексты ошибок
├── core/nfc         Формат метки, чтение, запись и привязка
├── core/settings    DataStore с адресом сервера, проверка адреса
├── data/model       Модели предметной области, трассировка кабеля до коммутатора
├── data/source      Демо-данные, работа с сервером, репозиторий
├── data/alerts      Журнал событий для экрана, счётчика и баннера
└── ui/
    ├── theme        Цвета, типографика, пружины и жесты (Motion)
    ├── navigation   Нижняя навигация с полупрозрачной панелью
    ├── map          Камера карты (жесты, инерция), отрисовка плана
    ├── devices      Список устройств
    ├── switchdetail Панель портов коммутатора
    ├── printers     МФУ и расходники
    ├── alerts       События и баннер нового события
    ├── nfc          Окно привязки метки
    ├── automation   Каталог сценариев
    └── settings     Настройки подключения
```

Анимации построены на пружинах с параметрами Apple (затухание и время отклика) вместо фиксированной
длительности: любое движение можно перехватить пальцем, а после жеста оно продолжается с той же скоростью.
Значения собраны в `ui/theme/Motion.kt`.
