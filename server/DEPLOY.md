# Развёртывание сервера NetAdmin на заводе

Пошаговая инструкция для ИТ-отдела. Сервер ставится одним из трёх способов:

| Способ | Где | Раздел |
|---|---|---|
| Пакет `.deb` | Сервер или виртуальная машина с Debian 12+ / Ubuntu 22.04+. Рекомендуется для постоянной работы. | 2 |
| Установщик Windows | Рабочий компьютер с Windows 10/11 или Windows Server 2016+, без Docker. | 3 |
| Docker Compose | Любой Linux с Docker. | 4 |

Сборки лежат на странице релиза [server-latest](https://github.com/iamlex92/ItManager/releases/tag/server-latest)
и обновляются при выпуске релиза (тег `v*` или ручной запуск, см. docs/CI.md).

Во всех способах сервер по умолчанию ничего не меняет на оборудовании: коммутаторы и мониторинг эмулируются,
`ALLOW_DEVICE_WRITES=false`. Подробнее в разделе «Режим только чтения».

## 1. Что нужно

- Debian/Ubuntu или Docker: 2 vCPU, 4 ГБ ОЗУ, 40 ГБ диска. Windows: любой рабочий компьютер, 2 ГБ свободной памяти и 2 ГБ диска.
- Сетевой доступ с сервера:
  - к VLAN управления коммутаторов (по умолчанию `10.99.0.0/24`) для SNMP (UDP 161) и ping;
  - к VLAN принтеров для SNMP;
  - к остальным подсетям для ping, если нужен контроль доступности.
- Сетевой доступ к серверу:
  - для телефонов: TCP 8000 из Wi-Fi ИТ-отдела или из VPN;
  - для коммутаторов, если нужны трапы: UDP 162.
- Для уведомлений в Telegram: исходящий HTTPS (443) до `api.telegram.org`, напрямую или через прокси.
- Постоянный IP-адрес сервера, например `10.99.0.50`.

## 2. Debian / Ubuntu: пакет .deb

Пакет ставит сервер в `/opt/netadmin`, службу systemd `netadmin` и берёт PostgreSQL из системы.

```sh
# скачать netadmin-agent_*.deb со страницы server-latest, затем:
sudo apt install ./netadmin-agent_*.deb
```

Установка сама:
- ставит PostgreSQL, если его нет, и создаёт в нём роль и базу `netadmin` (вход по локальному сокету, без пароля);
- создаёт `/etc/netadmin/netadmin.env` со случайными `API_TOKEN` и `SECRET_KEY` (права 640, root:netadmin);
- включает и запускает службу; копии базы складываются в `/var/lib/netadmin/backups`;
- в конце печатает адрес и ключ для приложения.

| Действие | Команда |
|---|---|
| Адрес и ключ для приложения | `sudo netadmin-agent info` |
| Настройки | `sudo nano /etc/netadmin/netadmin.env`, затем `sudo systemctl restart netadmin` |
| Состояние и журнал | `systemctl status netadmin`, `journalctl -u netadmin -f` |
| Копия базы сейчас | `sudo -u netadmin netadmin-agent backup` |
| Обновление | `sudo apt install ./netadmin-agent_<новая версия>.deb`: настройки и база остаются, миграции применяются при старте |
| Удаление | `sudo apt remove netadmin-agent`: база и копии остаются |

Служба работает от пользователя `netadmin`, не от root. Для трапов на порт 162 и для ping ей выданы только
нужные права (`CAP_NET_BIND_SERVICE`, `CAP_NET_RAW`). Трапы в этом варианте включены (`TRAP_LISTEN_PORT=162`).

## 3. Windows: установщик

`NetAdmin-Server-Setup.exe` со страницы server-latest. Нужны права администратора; Docker и Python не нужны.

Установщик:
- ставит программу в `C:\Program Files\NetAdmin`, вместе со своей базой PostgreSQL 16;
- данные, настройки, копии и журналы хранит в `C:\ProgramData\NetAdmin` (доступ только у администраторов и системы);
- регистрирует службу Windows «NetAdmin» с автозапуском; при первом запуске она создаёт базу (до минуты);
- открывает в брандмауэре TCP 8000 для доменной и частной сети (в общественной сети порт закрыт);
- в конце показывает адрес и ключ для приложения.

Встроенная база слушает только `127.0.0.1:54329`: с других компьютеров к ней не подключиться,
и она не мешает другому PostgreSQL на том же компьютере. Это тот же PostgreSQL, что и на сервере,
поэтому копию базы с Windows можно восстановить на Debian и наоборот (при том же `SECRET_KEY`).

| Действие | Как |
|---|---|
| Адрес и ключ для приложения | Пуск → NetAdmin → «Адрес и ключ для приложения» |
| Настройки | Пуск → NetAdmin → «Настройки сервера», затем перезапустить службу NetAdmin (`services.msc`) |
| Журналы | `C:\ProgramData\NetAdmin\logs` |
| Копия базы сейчас | в PowerShell от администратора: `& "C:\Program Files\NetAdmin\netadmin-agent.exe" backup` |
| Обновление | запустить новый установщик поверх: служба остановится, настройки и база останутся |
| Удаление | «Приложения» → NetAdmin Server: база, настройки и копии в `C:\ProgramData\NetAdmin` остаются |

Компьютер должен быть включён, пока сервером пользуются: при выключении или сне телефон увидит «Сервер недоступен».
Если компьютер в спящем режиме по ночам, копия базы сделается после пробуждения.

## 4. Docker Compose

Docker Engine и плагин Compose:

```sh
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER   # перелогиниться
```

Установка:

```sh
sudo mkdir -p /opt/netadmin && sudo chown $USER /opt/netadmin
cd /opt/netadmin
git clone https://github.com/iamlex92/ItManager.git
cd ItManager/server
cp .env.example .env
chmod 600 .env
```

Откройте `.env` в редакторе (`nano .env`) и задайте:

| Параметр | Что поставить |
|---|---|
| `API_TOKEN` | Длинный случайный ключ: `python3 -c "import secrets; print(secrets.token_urlsafe(32))"`. Этот же ключ вводится в приложении. |
| `POSTGRES_PASSWORD` | Свой пароль базы, до первого запуска. |
| `SECRET_KEY` | Ключ шифрования SNMP community и учётных данных в базе: `openssl rand -base64 32 \| tr '+/' '-_'`. Сохраните копию в менеджере паролей: без этого ключа зашифрованные значения и восстановленная из копии база не читаются. |
| `API_BIND` | IP сервера, на котором телефоны будут к нему обращаться (например `10.99.0.50`). `0.0.0.0` слушает на всех адресах. |
| `HAL_MODE` | `emulator`, пока не заведён логин SSH для коммутаторов; затем `real` (раздел 8a). |
| `ALLOW_DEVICE_WRITES` | **Оставить `false`.** |
| `MONITOR_MODE` | `real` (в новых установках по умолчанию): настоящие ping и SNMP-запросы только на чтение, уровни тонера и счётчики страниц МФУ, загрузка портов. `emulator`: опроса нет, цифры придумываются; годится только для проверки без сети. |
| `DISCOVERY_MODE` | `real` (по умолчанию): сканер сети работает с настоящей сетью, только чтение и только по кнопке. `emulator`: отвечает из учёта. |
| `TRAP_COMMUNITY` | Community, с которым коммутаторы шлют трапы. |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` | Уведомления о событиях в Telegram, см. раздел 9. Пустые: уведомлений нет. |
| `BACKUP_INTERVAL_HOURS`, `BACKUP_KEEP_DAYS` | Как часто делать копию базы и сколько дней их хранить (по умолчанию раз в сутки, 14 дней). |

Файл `.env` содержит секреты. Не коммитьте его и не пересылайте в мессенджерах.
В пакетах для Debian и Windows те же параметры лежат в `netadmin.env` и уже заполнены безопасными значениями.

Запуск:

```sh
docker compose up -d --build
docker compose ps                     # db, api и backup в состоянии running/healthy
curl http://localhost:8000/api/v1/health
```

Сервер сам запускается после перезагрузки машины (`restart: unless-stopped`).

### Проверка после установки (любой способ)

`http://<адрес>:8000/api/v1/health` показывает режимы:
- `"hal_mode": "emulator"`;
- `"device_writes_enabled"`: в эмуляторе `true`, потому что изменения уходят только в эмулятор;
- `"monitor_mode"`;
- `"secrets_encrypted": true`, если задан `SECRET_KEY` (в пакетах задан всегда);
- `"telegram_alerts": true`, если настроены уведомления в Telegram.

## 5. Подключение телефона

Быстрее всего по QR-коду:

1. На сервере откройте адрес и ключ: Windows: Пуск → NetAdmin → «Адрес и ключ для приложения»;
   Debian: `sudo netadmin-agent info`. Под ключом нарисован QR-код.
2. В приложении откройте ⚙ (правый верхний угол) → «Сканировать QR-код сервера» и наведите камеру на экран.
   Приложение заполнит адрес и ключ и само проверит соединение: если у компьютера
   несколько адресов (офисная сеть, VPN), останется тот, что отвечает.
3. Нажмите «Сохранить».

Вручную: введите адрес сервера, например `10.99.0.50` (порт 8000 подставится сам), вставьте `API_TOKEN`,
нажмите «Проверить соединение» и сохраните.

QR-код содержит ключ, как и сам экран с ключом: не фотографируйте его и не пересылайте. Если ключ утёк,
замените `API_TOKEN` в настройках, перезапустите службу и подключите телефоны заново.

Дальше «Устройства» → значок поиска → «Сканер сети»: укажите подсети и SNMP community только для чтения, затем «Сканировать» и «Добавить в учёт».

## 6. Доступ извне через VPN

Сервер не публикуется в интернет. Снаружи к нему подключаются только через заводской VPN.

- **Если VPN уже есть** (например на межсетевом экране), разрешите из VPN-подсети доступ к `IP_сервера:8000/tcp` и ни к чему больше.
- **Если VPN нет**, проще всего поднять WireGuard на шлюзе:
  1. Создайте отдельного пира для каждого телефона.
  2. В `AllowedIPs` на телефоне укажите только адрес сервера, например `10.99.0.50/32`.
  3. На телефоне установите приложение WireGuard и импортируйте конфиг по QR-коду.

Ограничьте доступ на самом сервере (пример для ufw; `10.8.0.0/24` это VPN, `10.10.10.0/24` это ИТ-отдел):

```sh
sudo ufw allow from 10.8.0.0/24 to any port 8000 proto tcp
sudo ufw allow from 10.10.10.0/24 to any port 8000 proto tcp
sudo ufw allow from 10.99.0.0/24 to any port 162 proto udp    # трапы от коммутаторов
sudo ufw allow OpenSSH
sudo ufw enable
```

Docker публикует порты в обход ufw. Поэтому ограничивайте доступ и параметром `API_BIND` (адрес внутреннего интерфейса), и правилами на межсетевом экране перед сервером.

**Cisco ASA (AnyConnect) — приложение подключает VPN само.** В приложении: «Ещё → Сервер и доступ →
Подключение и безопасность → VPN завода». Включите «Подключать автоматически» и укажите название подключения
в Cisco Secure Client или адрес ASA. Один раз в самом Cisco Secure Client: «Настройки → Внешнее управление →
Включено». Дальше при открытии приложения вне завода, если сервер не отвечает, оно просит AnyConnect подключиться
(`anyconnect://connect`) и обновляет экраны, когда тот вернёт `itmanager://vpn/connected`. Пароль приложение не
знает: он вводится или хранится в AnyConnect, удобнее вход по сертификату. В Android одновременно работает одна
VPN: подключение завода заменяет личный VPN, кнопка «Отключить VPN завода» возвращает телефон ему.

## 6a. Настройки сервера без правки файла

Почти всё из `netadmin.env` меняется в веб-консоли («Ещё → Настройки сервера») и в приложении
(«Ещё → Система → Настройки сервера»): работа с коммутаторами, опрос устройств и SNMP (в том числе v3), трапы,
компьютеры домена и сценарии (режим, учётная запись домена, контроллер AD, WinRM), Telegram, резервные копии.

- Сохранённое хранится в базе (секреты — зашифрованными) и заменяет значение из файла; у каждой настройки видно,
  откуда она: «задано здесь», «из netadmin.env» или «по умолчанию». «Вернуть из netadmin.env» убирает замену.
- Новые значения начинают действовать после перезапуска: кнопка «Перезапустить сервер» перезапускает службу
  (systemd, служба Windows или контейнер Docker) — сервер недоступен 10–30 секунд.
- В приложении сохранение подтверждается биометрией. Каждое изменение и перезапуск — в журнале.
- В файле остаются только `DATABASE_URL`, `API_TOKEN`, `SECRET_KEY`, `API_BIND`/`API_PORT` и пути к папкам:
  без них сервер не запустится или не будет доступен.
- «Компьютеры домена» можно перевести в настоящий режим отдельно от «Сценариев» (`PC_MODE`).

## 7. Режим только чтения

| Что | Как защищено |
|---|---|
| Изменения на коммутаторах (VLAN, shutdown, перезапуск порта, write memory) | Пока `ALLOW_DEVICE_WRITES=false`, сервер отвечает 403 и ничего не отправляет. При `HAL_MODE=real` с коммутаторов только читается состояние портов и конфигурация. |
| Мониторинг, сканер сети, загрузка портов | Только ping и SNMP GET/GETNEXT. Команд SET нет. |
| Сценарии AD и серверов | Выполняются в эмуляции, учётных данных AD на сервере нет. |
| Журнал | Каждое действие, включая заблокированные попытки, пишется в журнал аудита. |
| Секреты | SNMP community и учётные данные хранятся в базе зашифрованными (`SECRET_KEY`). API их не отдаёт, только признак «задано». В журнал аудита они не попадают. |

Включать `ALLOW_DEVICE_WRITES` можно только по отдельному решению, после проверки на одном коммутаторе в окно обслуживания.

## 8. Коммутаторы: SNMP и трапы

Нужна только read-only community, права на запись не нужны.

Cisco IOS:

```
snmp-server community <ro-community> RO <ACL-с-адресом-сервера>
snmp-server enable traps snmp linkdown linkup
snmp-server host 10.99.0.50 version 2c <trap-community>
lldp run
```

Eltex MES:

```
snmp-server server
snmp-server community <ro-community> ro
snmp-server host 10.99.0.50 traps version 2 <trap-community>
lldp run
```

Перед вводом команд согласуйте окно работ: это изменения конфигурации самих коммутаторов, и сервер их не делает.

### Линк портов без SSH

При `MONITOR_MODE=real` и `HAL_MODE=emulator` сервер читает с коммутаторов по SNMP (community задаётся в форме
коммутатора: «Изменить» → «SNMP community»; только чтение) состояние каждого порта: есть ли линк (`ifOperStatus`), выключен ли порт
(`ifAdminStatus`) и скорость (`ifHighSpeed`) — раз в `POLL_INTERVAL_SECONDS`, но не чаще 15 с, и по кнопке
«Обновить» в карточке. Порты сопоставляются по `ifName`, поэтому подходят и порты из импорта конфигурации.
Пропавший линк поднимает событие LINK_DOWN. VLAN и режим портов берутся из учёта (импорт конфигурации), смена
VLAN в этом режиме остаётся в учёте и на коммутатор не уходит — для этого нужен `HAL_MODE=real` (раздел 8a).

## 8a. Коммутаторы Cisco IOS и Eltex MES по SSH

При `HAL_MODE=real` сервер сам заходит на коммутаторы по SSH: читает состояние портов (`show interfaces status`,
`show running-config`, `show vlan brief`, `show power inline`), показывает running-config, выполняет ping и
traceroute с коммутатора. Изменения (VLAN, shutdown, перезапуск порта, сохранение конфигурации) отправляются
только при `ALLOW_DEVICE_WRITES=true` и после подтверждения в приложении или веб-консоли.

1. На коммутаторе — отдельная учётная запись для сервера с privilege 15 (или обычная плюс `enable`):

   Cisco IOS:
   ```
   username netadmin privilege 15 secret <пароль>
   ip ssh version 2
   line vty 0 15
    transport input ssh
    login local
   ```

   Eltex MES:
   ```
   username netadmin password <пароль> privilege 15
   ip ssh server
   line ssh
    login authentication default
   ```
2. В приложении или веб-консоли: «Ещё → Учётные данные» → добавить вид **SSH** (логин и пароль).
3. Укажите этот логин в карточке каждого коммутатора («Изменить» → «Логин SSH») или один на все:
   `SWITCH_CREDENTIAL=<имя учётных данных>` в `netadmin.env`.
4. Если вход попадает в режим `>`, сервер сам выполняет `enable` с тем же паролем; другой пароль enable задаётся в
   `SWITCH_ENABLE_SECRET`.
5. `HAL_MODE=real`, перезапуск службы. Плашка вверху веб-консоли покажет «коммутаторы: real · запись выключена».

| Параметр | По умолчанию | Что делает |
|---|---|---|
| `SWITCH_CREDENTIAL` | пусто | Учётные данные SSH для коммутаторов, у которых в карточке логин не выбран. |
| `SWITCH_ENABLE_SECRET` | пусто | Пароль `enable`, если он отличается от пароля входа. |
| `SWITCH_SSH_PORT` | `22` | Порт SSH коммутаторов. |
| `SWITCH_CONNECT_TIMEOUT_SECONDS` / `SWITCH_COMMAND_TIMEOUT_SECONDS` | `15` / `30` | Ожидание подключения и ответа на команду. |
| `SWITCH_KNOWN_HOSTS` | пусто | Файл known_hosts с ключами коммутаторов. Пусто — ключ хоста не проверяется (сеть управления доверенная). |

Опрос портов в этом режиме — одно SSH-подключение к каждому коммутатору не чаще раза в минуту
(`POLL_INTERVAL_SECONDS`, но не меньше 60). Сервер поддерживает и старые прошивки (SHA-1, CBC, ssh-rsa).
Не отвечает коммутатор — он помечается «Не в сети»; нет логина — состояние портов не меняется, в журнале
службы предупреждение. Ошибки видны и в приложении: «нет логина SSH», «вход отклонён», «коммутатор не отвечает».

Перед включением `ALLOW_DEVICE_WRITES=true` проверьте смену VLAN и сохранение на одном коммутаторе в окно работ.

## 9. Уведомления в Telegram

1. В Telegram напишите @BotFather → `/newbot`, задайте имя. Он пришлёт токен вида `123456:ABC...`.
2. Создайте группу ИТ-отдела (или возьмите существующую) и добавьте в неё бота.
3. Напишите в группу любое сообщение и откройте с компьютера
   `https://api.telegram.org/bot<токен>/getUpdates`. В ответе найдите `"chat":{"id":-100...}`: это `TELEGRAM_CHAT_ID`.
4. Впишите оба значения в настройки и перезапустите сервер: Docker: `.env` и `docker compose up -d`;
   Debian: `/etc/netadmin/netadmin.env` и `sudo systemctl restart netadmin`; Windows: «Настройки сервера» и перезапуск службы NetAdmin.
5. Проверка: в `health` должно быть `"telegram_alerts": true`, затем
   ```sh
   curl -X POST -H "Authorization: Bearer $API_TOKEN" http://localhost:8000/api/v1/notifications/telegram/test
   ```
   В группу придёт «Проверка связи NetAdmin». Если нет, ответ скажет почему (неверный токен, бот не в чате, нет сети).

Что приходит:
- события от уровня `TELEGRAM_MIN_SEVERITY` (по умолчанию предупреждения и критичные): упавший порт,
  недоступный коммутатор, сервер, МФУ или камера, кончающийся тонер;
- только если событие не закрылось за `TELEGRAM_DELAY_SECONDS` (60 секунд), чтобы мигающий порт не будил людей;
- «✅ Восстановлено», когда событие закрылось (выключается `TELEGRAM_NOTIFY_RESOLVED=false`);
- не больше `TELEGRAM_MAX_PER_MINUTE` сообщений в минуту, остальные считаются и упоминаются в следующем.

Серверу нужен исходящий HTTPS до `api.telegram.org`. Если интернет только через прокси, задайте `TELEGRAM_PROXY`.
Токен бота в журналы не пишется. Сообщения идут только наружу, на оборудование уведомления не влияют.

## 10. Резервные копии

Пакеты для Debian и Windows делают копии сами (служба NetAdmin, первая копия через минуту после запуска):

| | Debian | Windows |
|---|---|---|
| Папка | `/var/lib/netadmin/backups` | `C:\ProgramData\NetAdmin\backups` |
| Копия сейчас | `sudo -u netadmin netadmin-agent backup` | `netadmin-agent.exe backup` от администратора |
| Восстановление | `sudo systemctl stop netadmin`, `sudo -u netadmin netadmin-agent restore <файл>`, `sudo systemctl start netadmin` | остановить службу NetAdmin, `netadmin-agent.exe restore <файл>`, запустить службу |

Расписание и срок хранения: `BACKUP_INTERVAL_HOURS` и `BACKUP_KEEP_DAYS` в `netadmin.env`. Копируйте папку на другое
хранилище так же, как ниже для Docker (на Windows, например, заданием планировщика с `robocopy`).

Docker:

- Сервис `backup` делает `pg_dump` в каталог `backups/` рядом с `docker-compose.yml`. Файлы называются `netadmin-ГГГГММДД-ЧЧММСС.dump`.
- Копии старше `BACKUP_KEEP_DAYS` удаляются.
- Копируйте каталог `backups/` с сервера, например ночным заданием на файловое хранилище:
  ```sh
  # crontab -e
  30 3 * * * rsync -a /opt/netadmin/ItManager/server/backups/ backup@nas:/netadmin/
  ```
- Проверить, что копии делаются: `docker compose logs backup | tail`.
- Сделать копию прямо сейчас: `docker compose exec backup /bin/sh /backup.sh --once`.
- Восстановить из копии (останавливает API на время восстановления и спрашивает подтверждение):
  ```sh
  ./scripts/restore.sh backups/netadmin-20261025-030000.dump
  ```

База хранится в томе Docker `pgdata`. Она переживает пересборку, обновление и `docker compose down`. Удаляет её только `docker compose down -v`; эту команду на заводе не используйте.

## 11. Обновление

Debian и Windows: поставить новый пакет поверх (разделы 2 и 3). Настройки и база сохраняются, копия базы
делается через минуту после старта новой версии; для спокойствия сделайте её и перед обновлением.

Docker:

```sh
cd /opt/netadmin/ItManager/server
docker compose exec backup /bin/sh /backup.sh --once   # копия перед обновлением
git pull
docker compose up -d --build
curl http://localhost:8000/api/v1/health
```

Миграции базы применяются автоматически при старте сервера, в любом варианте.

## 12. Если что-то не так

| Симптом | Что проверить |
|---|---|
| Приложение: «Сервер недоступен» | Телефон в Wi-Fi завода или VPN включён; с телефона открывается `http://IP:8000/api/v1/health`; `API_BIND` и межсетевой экран. |
| «Сервер отклонил API-токен» | `API_TOKEN` в настройках и в приложении совпадают; после правки перезапустить сервер (раздел 9, шаг 4). |
| Импорт конфигурации прошёл, но линк портов не настоящий | Конфигурация не содержит состояния линка: его сервер читает сам. Нужно `MONITOR_MODE=real` (линк по SNMP) и на коммутаторе SNMP v2c с community из карточки коммутатора, доступный с адреса сервера. Если SNMP не отвечает, «Обновить» в карточке коммутатора покажет ошибку. |
| У МФУ счётчик страниц растёт при каждом опросе, а расходников нет | Сервер в режиме эмуляции: в `netadmin.env` стоит `MONITOR_MODE=emulator` (так было в установках до 1.0). Поставьте `MONITOR_MODE=real` и перезапустите службу (`sudo systemctl restart netadmin` или служба NetAdmin в Windows). Режим виден в веб-консоли вверху справа и в приложении в проверке соединения. Если и в `real` расходников нет: проверьте SNMP community МФУ в карточке устройства и что на МФУ включён SNMP v2c. |
| Сканер ничего не находит | Посмотрите предупреждения над результатом. `DISCOVERY_MODE=real` в настройках (в старых установках может стоять `emulator`); есть ли маршрут от сервера до подсети; не режет ли межсетевой экран ping и TCP от сервера. Debian: пакет `iputils-ping` установлен. |
| Сканер не находит имена и связи | Без SNMP тип определяется по портам и MAC, а связи между коммутаторами только по SNMP: совпадает ли community, открыт ли UDP 161 от сервера до VLAN управления, включён ли LLDP. |
| Нет MAC и производителя | Сервер видит MAC только устройств своей подсети (ARP). Для других подсетей MAC берутся из таблиц коммутаторов по SNMP. |
| API не стартует: `SecretsUnavailable` | `SECRET_KEY` в настройках не тот, которым шифровали базу (или пустой). Верните прежний ключ. |
| Не приходят уведомления в Telegram | `telegram_alerts` в `health`; тестовое сообщение (раздел 9) скажет причину; `docker compose logs api \| grep -i telegram`. |
| Windows: служба NetAdmin не запускается | Журналы в `C:\ProgramData\NetAdmin\logs`: `netadmin-service.*.log` (сервер) и `postgresql.log` (база). Порт 8000 или 54329 занят другой программой? |
| Debian: служба не запускается | `journalctl -u netadmin -n 100`; работает ли PostgreSQL: `systemctl status postgresql`. |
| Логи | Docker: `docker compose logs -f api`; Debian: `journalctl -u netadmin -f`; Windows: `C:\ProgramData\NetAdmin\logs`. |

## 13. Runbooks с настоящим AD

По умолчанию сценарии на вкладке «Автоматизация» работают с учебной средой: настоящий AD не затрагивается.
Режим `RUNBOOK_MODE=real` подключает два вида сценариев:

| Сценарий | Как работает | Что нужно |
|---|---|---|
| Сброс пароля, разблокировка, включение и отключение учётной записи | LDAP по TLS к контроллеру домена | `AD_LDAP_URL` |
| Проверка прав на папку | `Get-Acl` по WinRM на файловом сервере, группы пользователя из AD | `RUNBOOK_FILE_SERVERS` |

Резервные копии баз, снапшоты ВМ и перезапуск служб в этом режиме не показываются: для них пока есть только эмуляция.

**Сначала только чтение.** Пока `ALLOW_RUNBOOK_WRITES=false`, сценарии, которые меняют AD, показывают
учётную запись и что нужно сделать, но ничего не меняют. Проверку прав на папки флаг не затрагивает: она только читает.

1. Заведите в AD служебную учётную запись, например `svc-netadmin`. Для чтения хватит обычного пользователя домена.
   Для изменений делегируйте ей на нужные OU права «Reset password», запись `lockoutTime` и `userAccountControl`
   (мастер «Делегирование управления» в «Пользователи и компьютеры AD»). Администратором домена её не делайте.
2. Для проверки прав на папки она должна подключаться к файловым серверам по WinRM (`Enable-PSRemoting` на сервере;
   права: группа «Remote Management Users» и чтение ACL нужных папок).
3. В приложении: ⚙ → «Учётные данные» → добавьте её с именем `ad-runbooks`, тип WinRM, логин в виде
   `svc-netadmin@factory.local`. Пароль хранится на сервере зашифрованным.
4. В файле настроек сервера:

   ```
   RUNBOOK_MODE=real
   RUNBOOK_CREDENTIAL=ad-runbooks
   AD_LDAP_URL=ldaps://dc01.factory.local
   RUNBOOK_FILE_SERVERS=fs01,fs02
   ALLOW_RUNBOOK_WRITES=false
   ```

   Если у контроллеров домена нет сертификата для LDAPS, сервер не подключится: открытый LDAP не используется,
   потому что по нему уходит пароль. Сертификат выдаёт центр сертификации домена (AD CS). Если его корневого
   сертификата нет в системе, укажите файл в `AD_CA_FILE=/etc/netadmin/factory-ca.pem`. Вместо `ldaps://`
   можно `ldap://` с `AD_START_TLS=true`.
5. Перезапустите службу. В приложении ⚙ → «Проверить соединение» покажет «runbooks: реальный AD, только чтение».
6. Проверьте «Проверка прав на папку» и «Разблокировка» на своей учётной записи. Когда всё показывает верно,
   поставьте `ALLOW_RUNBOOK_WRITES=true` и перезапустите службу.

Ограничения, которые не отключаются:

- Учётные записи с `adminCount=1` (администраторы домена и другие защищённые группы) с телефона не меняются.
- Логин отправляется по WinRM только на серверы из `RUNBOOK_FILE_SERVERS`, а не на любой адрес, введённый в приложении.
- Каждый запуск записывается в журнал аудита. Временный пароль показывается один раз и в журнал не попадает.
- Права общего ресурса (Share) и локальные группы файлового сервера, кроме Users, в проверке прав не учитываются.

## 13a. Групповые политики

«Ещё → Групповые политики» в веб-консоли и в приложении: все GPO домена, какие действуют, где они связаны,
их параметры (административные шаблоны) и компьютеры, на которые они действуют; на странице компьютера домена —
«Политики на ПК» (что он применил на самом деле, по `gpresult`). Можно менять состояние политики, связи
с подразделениями (включить, выключить, принудительно, убрать, добавить), параметры реестра, создавать и удалять
политики и сразу применять их (`gpupdate /force` на выбранных компьютерах).

Как включить настоящий режим («Ещё → Настройки сервера» → «Компьютеры домена и сценарии»):

1. «Компьютеры домена»: «Настоящие (WinRM)», «Учётная запись домена» — учётная запись с правом править GPO
   (Domain Admins). Если Samba не принимает вход `ДОМЕН\имя`, укажите `имя@домен.local`.
2. «Контроллер домена»: `ldaps://<контроллер>`, например `ldaps://rukrsrvdc01.ecotehs.local`. Сервер работает
   с политиками напрямую: объекты и связи — по LDAPS (порт 636), параметры (`Registry.pol`) — в SYSVOL по SMB
   (порт 445). Так работает и с **Samba AD (Astra Linux, ALT)**, и с Windows; ни WinRM, ни PowerShell на
   контроллере не нужны.
3. «Сертификат контроллера (ЦС)»: если сертификат LDAPS самоподписан или выдан своим ЦС. У Samba это содержимое
   `/var/lib/samba/private/tls/ca.pem` на контроллере (`sudo cat /var/lib/samba/private/tls/ca.pem`), вставьте
   его целиком.
4. «Сервер GPMC» оставьте пустым. Его задают, только если есть Windows-сервер с GPMC и WinRM и нужно
   работать через PowerShell GroupPolicy с «Резервными копиями GPO».
   Без него политики создаются и удаляются прямо здесь, как `samba-tool gpo create` и `samba-tool gpo del`:
   объект в AD и папка в SYSVOL; при удалении сначала снимаются все её связи. Права новой политики — как у
   созданной samba-tool до `ntacl sysvolreset`: применяется к «Прошедшим проверку», папка наследует права
   папки Policies. Комментарий к политике в этом режиме не сохраняется.
5. Для изменений — «Разрешить изменения». В приложении каждое изменение подтверждается биометрией, в консоли —
   вопросом. Всё пишется в журнал с прежним значением. После правки параметров сервер повышает версию политики
   (GPT.INI и versionNumber), и компьютеры забирают её при следующем обновлении или по «Применить сейчас».

«Компьютеры, на которые действует» считаются по связям, блокировке наследования и фильтру безопасности; WMI-фильтры
не учитываются — точную картину по компьютеру даёт «Политики на ПК». Параметры, которые не хранятся в реестре
(сценарии, параметры безопасности, предпочтения), видны в «Отчёте» и правятся в GPMC.

## 13b. Компьютеры с Astra Linux и удалённая помощь

«Компьютеры домена» работают и с Astra Linux SE 1.7 («Смоленск»), введёнными в домен через winbind. Сервер сам
определяет платформу: отвечает WinRM (5985) — Windows, только SSH (22) — Astra Linux. Для Astra доступны сведения,
диски, крупные папки, процессы, очистка, перезагрузка, консоль bash, `samba-gpupdate`, обновление пакетов
(`astra-update`, в фоне) и выдача/снятие sudo (`/etc/sudoers.d/netadmin-admins`, с проверкой `visudo`).

Что нужно на ПК с Astra:

1. Включённый SSH: `sudo systemctl enable --now ssh`.
2. Учётная запись с sudo. Либо отдельная («Настройки сервера» → «Учётная запись для Astra Linux», вид SSH), либо
   доменная («Учётная запись домена»): тогда ей нужен вход по SSH и sudo, например
   `echo '%ECOTEHS\\domain\ admins ALL=(ALL:ALL) ALL' | sudo tee /etc/sudoers.d/domain-admins`.
3. Для удалённой помощи — `sudo apt install x11vnc`.

**Удалённая помощь** — кнопка на странице компьютера и в карточке устройства:

- Windows: панель показывает `msra.exe /offerra ИМЯ-ПК` и даёт скачать ярлык; запускается на вашем компьютере.
  Нужны шаблоны политики «Предлагать удалённую помощь» (вы — в списке помощников), «Запрос удалённой помощи»,
  «Брандмауэр: входящие подключения → Удалённый помощник» и, чтобы видеть окна UAC, «Запросы UAC во время
  удалённой помощи».
- Astra Linux: сервер запускает на ПК `x11vnc` для экрана вошедшего пользователя с одноразовым паролем на 2 минуты
  (порт 5900–5910). Пользователь видит окно с вопросом и нажимает «Yes». Подключение — любым VNC-клиентом
  (TigerVNC, Remmina) по адресу и паролю из панели; после отключения x11vnc закрывается. Окно повышения прав
  на Astra открывается на том же экране, пароль администратора вы вводите сами. VNC не шифруется — только внутри
  сети; если на ПК включён брандмауэр, откройте порты 5900–5910 для своей подсети.

## 14. Веб-консоль

Откройте в браузере на любом компьютере в сети `http://<адрес агента>:8000/admin` (адрес покажет
`netadmin-agent info`) и войдите по API-токену. В консоли можно:

- загрузить план здания (PNG, JPEG или SVG; PDF загружается с телефона), подвинуть и масштабировать его;
- расставлять, добавлять и править устройства, соединять их кабелями, рисовать поверх плана;
- запускать сканирование сети (только чтение) и добавлять найденное в инвентарь;
- добавлять свои скрипты: они появляются в приложении на вкладке «Автоматизация».

Всё, что внесено в консоли, сразу видно в приложении: телефон получает уведомление по WebSocket и перечитывает данные.
Консоль меняет только инвентарь в базе. Свои скрипты не выполняются: запуск показывает текст
с подставленными параметрами (эмуляция), независимо от RUNBOOK_MODE.

Страница отдаётся без токена, но сама данных не содержит: все запросы из неё идут в тот же API с токеном.
Если токен отметить «Запомнить на этом компьютере», он хранится в браузере; на общих компьютерах не отмечайте.
